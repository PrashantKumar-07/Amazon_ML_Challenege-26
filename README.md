# Amazon ML Challenge 2026 — Business Entity Resolution

![Leaderboard F0.5](https://img.shields.io/badge/public%20LB%20F0.5-0.990-brightgreen)
![License](https://img.shields.io/badge/license-MIT-blue)
![Python](https://img.shields.io/badge/python-3.10-blue)

Match every Source 1 business entity against noisy Source 2 / Source 3 records (0..many matches per
entity, plus an unseen country — France — at test time). Scored with macro-averaged **F0.5**
(precision-heavy), singletons included.

## Results

| Submission | What changed | Public LB |
|---|---|---|
| v1 | blocking + XGBoost + threshold | 0.969 |
| v4 | token-level near-miss features, density-aware selection | 0.979 |
| v5 | stage-2 rescoring (CE for seen countries) | 0.983 |
| v6 | unseen-country logit blend | 0.985 |
| v7 | XLM-R for seen countries (rejected) | 0.984 |
| **v8 (shipped)** | **seen blend + unseen house-number gate** | **0.990** |

Validation on training data (macro F0.5): stage-1 OOF **0.9872** (US 0.9877, India 0.9865),
test-like distractor density **0.9863**, unseen country **0.9521**; stage-2 in-country **0.9904**.
Blocking pair recall **98.9%** (US 99.14%, India 98.59%; perfect-matcher ceiling 0.9966).
Models and thresholds were selected on a density simulation + leave-one-country-out split, never on
plain OOF alone. Full tables and ablations: [`Documentation_template.md`](Documentation_template.md).

The shipped file is [`output/matching_results.tsv`](output/matching_results.tsv): **5,865,431 matches**
across 1,732,544 S1 entities (98,671 empty) — France 3.44, India 3.37, US 3.38 matches/entity.

## How it works

1. **Normalise + cross-script token map** — placeholders removed, NFKC, Indic-script tokens mapped to
   Latin (map learned from training pairs only), symbols fixed (`N°` → space, not `deg`).
2. **Blocking (GPU)** — exact char-3-gram TF-IDF, each record retrieves top-10 S1 under two blockers
   (name+address, name), same country label. 186.4M test pairs, reduction ratio 0.9999916.
3. **Stage-1** — 89 string/context/token features → XGBoost, 5-fold OOF grouped by S1, early stopping,
   threshold 0.80. Used as a filter (p ≥ 0.003) for stage-2.
4. **Stage-2** — 113 features (89 capped + 18 edit-operation + 6 cross-encoder: e5-small and
   xlm-roberta-base, both MIT, ~0.4B params total) → per-country decision with a house-number gate for
   the unseen country.

## Repository layout

```
├── output/
│   └── matching_results.tsv        # final matches — the leaderboard file (v8)
├── code/
│   └── business_entity_resolution/
│       ├── src/                    # stage-1 pipeline (blocking → features → XGBoost → decision)
│       ├── stage2/                 # stage-2 rescoring + v8 decision (combine8b.py)
│       ├── artifacts/              # stage-1 models + token map + decision (inference, no retraining)
│       ├── tests/                  # pytest suite (unit + end-to-end incl. extreme cases)
│       ├── README.md               # setup, quick start, full retraining, hardware
│       └── requirements.txt        # pinned dependencies
├── Documentation_template.md       # methodology write-up (blocking, features, ablations, errors)
└── ML_problem_statement.pdf        # challenge problem statement
```

Not in git (too large / not redistributable): the dataset (2.4 GB, get it from the challenge portal),
`output/candidate_pairs.tsv` (2.3 GB — regenerated by `src/blocking.py`), `work/` caches, and the
`models_hf/` cache.

## Quick start

```bash
cd code/business_entity_resolution
python3.10 -m venv .venv && source .venv/bin/activate
pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt

# stage-1 test predictions from the shipped models (no training)
python -m src.pipeline --mode inference --artifacts artifacts \
    --data-dir /path/to/student_resource/dataset \
    --work /path/to/work --out /path/to/output --gpus cuda:0 --threads 32

# validate
python3 /path/to/student_resource/utils/validate_submission.py \
    --matching /path/to/output/matching_results.tsv \
    --candidate /path/to/output/candidate_pairs.tsv --test-dir /path/to/student_resource/dataset/test
```

Full retraining (`--mode full`) and the stage-2 rebuild to the v8 file are documented in
[`code/business_entity_resolution/README.md`](code/business_entity_resolution/README.md) and
[`code/business_entity_resolution/stage2/README.md`](code/business_entity_resolution/stage2/README.md).
Stage-2 paths are portable (`BER_ROOT` / `BER_W4` / `BER_W5` overrides, no machine-specific strings).
